## Acceptance checklist

- Navigation: create → session → home retains the new session despite delayed projection; sleep/wake state agrees across rail and page; transient list failure retains usable navigation; authorization failure clears retained data.
- Cmd K: immediate open/focus; title/repository/branch multi-term and reversed-term matching; relevant result selected; no accidental create for short queries; Arrow Up/Down, Home/End, Enter, Escape; active item remains visible; no hover-induced scroll jump; clear no-match state; mobile close/entry.
- Mobile shell: 320/390px widths; no horizontal page overflow; drawer focus containment and background isolation; close/backdrop/Escape and route-change dismissal; opener focus restoration; safe-area padding.
- Creation: empty/invalid/loading/pending/failure states, repository discovery/manual entry, optional title/time, attachments, duplicate-submit prevention, retained retry intent.
- Lifecycle: preparing/saving/sleeping/waking/reconciling/failed/gone remain distinguishable; no optimistic success for ambiguous outcomes; destructive confirmation preserved.
- Conversation: composer focus/blur keeps draft, multiline growth, selection visible at narrow widths, connection/retry/queue feedback, reading older history does not pull the user to the tail.
- Workbench: Summary, Diff, patch change/retry, keyboard exit/focus return, lazy Terminal, disabled/disconnected fixture services labeled honestly.
- Rich content: long titles/paths, code/table overflow, Markdown links/images, valid and incomplete Mermaid, screenshot evidence, long history.
- Performance: production chunk comparison; no optional Terminal request before opening; hidden polling pauses; visible polling resumes; stale requests cannot commit; unchanged Markdown source avoids re-lexing.
- Accessibility/motion: focus/selected/disabled/error/loading/empty states, reduced motion, 200% zoom, 10%-speed review of changed motion; real mobile keyboard/device checks remain distinct from emulation.

## React effect audit

Baseline: 25 `useEffect` / `useLayoutEffect` calls across the UI. Count is an inventory, not a quality target. React recommends deriving render data directly, handling interaction-specific work in handlers, and using effects to synchronize external systems with cleanup. ## Implemented versus remaining

Implemented: root catalog ownership with verified actor corrections and request fencing; new-session reconciliation; no-store session reads; retained list/error states; actor-only lifecycle polling; tokenized Cmd K with keyboard navigation and mobile entry; drawer focus containment and background isolation; mobile composer expansion and visible configuration; lazy Terminal; memoized Markdown parsing; hidden-tab conversation/Summary polling pause; stale patch publishing guard; reachable rich-content/runtime fixtures; settings unavailable state, all five local preview panes, draft preservation, local mutation isolation, mobile controls and save feedback.

Remaining improvements and proof boundaries:

- Summary still owns a second conversation read while open. Sharing its snapshot with the live transcript needs a deliberate ownership change.
- Cmd K remains unavailable in the standalone Settings shell. Reusing the palette there is a follow-up.
- The audit's broader metadata-size, token-cleanup and evidence-thumbnail outline suggestions were gathered, not applied everywhere. Conversation animation restarts were not reproduced and are not claimed as fixed.
- The preview covers static lifecycle states and populated settings; successful real creation, sleep/wake, terminal transport, providers, devices and stats require a connected backend. This is not an all-services simulator.
- Production CPU/interaction timings, real-device keyboards, 200% browser zoom and slowed-motion visual proof remain unmeasured. Responsive emulation establishes layout behavior, not those guarantees.
- The existing Vitest/Vite shutdown warning remains after successful assertions and exit code 0.

## Considered but rejected

| Location            | Candidate                                                                        | Rejected because                                                                                                             |
| ------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Shared UI           | Add a motion library and animate every navigation/result                         | Existing CSS/StyleX is sufficient; high-frequency navigation should remain immediate                                         |
| Session rail        | Add virtualization immediately for approximately 60 fixture sessions             | Source size alone does not establish a rendering bottleneck; conditional palette rendering and measured profiling come first |
| Lifecycle/catalog   | Invent optimistic SessionModel data from the create response                     | Create returns insufficient authority data; only a verified actor read may establish lifecycle state                         |
| React UI            | Delete all effects or replace each with a custom hook                            | Effects that own browser/network/library lifetimes are necessary; hiding them does not fix ownership                         |
| Mermaid/diff assets | Treat all generated JS as initial-page transfer or replace libraries immediately | Most large grammars are lazy chunks. Initial waterfall and first-tool load are separate measurements                         |
