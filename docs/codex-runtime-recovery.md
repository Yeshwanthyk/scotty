# Codex runtime failure and sleep recovery

The Session Sandbox Durable Object owns the persisted Session state, operation lease, runtime generation, and backup handle. `Warm` records the last confirmed admission under that generation. The container's Codex runtime owns only the live native process, thread/turn adapters, and bounded conversation projection. A live `ready: false` snapshot is a newer health observation; it does not itself commit a Session state transition. The public conversation projects that health and the failed turn, while the Session projection remains `Warm` until a fenced lifecycle transition commits.

| Transition             | Preconditions and owner                                                                          | Durable write and publication                                                                                                                                                                                                                             | Retry and recovery                                                                                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native event failure   | Runtime fences event thread and turn; rejected stale traffic fails its process generation.       | Runtime projects a failed turn and `ready: false`; no Session record or backup changes.                                                                                                                                                                   | Admission stops; matching client message receipts retain accepted or unknown delivery.                                                                           |
| Sleep quiesce          | Session actor leases the current Warm generation; Codex has an admitted initial thread and turn. | Runtime stops the native parent, saves bounded failed-turn history and validated allowlisted native rollout files to workspace `.scotty/codex-state.json`. An admitted failure remains `prompt: failed`, never a fabricated native terminal notification. | Missing turn identity, missing/invalid native file, uncertain process exit, or invalid saved history fails the operation visibly. No backup success is reported. |
| Sleep backup           | Session actor owns the same transition lease.                                                    | Workspace sync and immutable R2 backup confirmation precede runtime stop and the committed `Sleeping` state. The backup retains native thread and initial turn identities.                                                                                | The actor retries or reconciles the transition using its persisted proof; it never treats a local save alone as a confirmed backup.                              |
| Resume                 | Session actor requires its current backup and commits a fresh runtime generation.                | Restored native files are validated against the backup identity; native `thread/resume` and `thread/read` must verify the same durable thread before Warm readiness is published.                                                                         | Failed resume retains failure and backup proof; no new native conversation or automatic replay of the failed user turn is admitted.                              |
| Follow-up after resume | Fresh runtime verifies current generation and thread; Session remains Warm.                      | A new client message ID admits one distinct native turn. A saved accepted receipt can be reconciled without dispatch; unknown receipt remains unknown.                                                                                                    | A failed original turn stays visible; the user can choose how to continue.                                                                                       |

The failed native turn is not claimed to have completed or interrupted. The saved record deliberately preserves `prompt: failed` and a matching failed history entry, with no replay of that message. A freshly verified resumed runtime may accept the next follow-up; the failed generation cannot. `runtimeStopped` and follow-up availability come from the current fenced runtime snapshot, so the restored historical failure does not render the new process as stopped. An upstream failure exposes only its pinned native error category and optional numeric HTTP status; the provider's message and additional details are never projected.

New Codex threads register Hatch and browser evidence tools at native `thread/start`; the pinned app-server persists those registrations in its rollout for resume. Native `thread/resume` has no registration field. Threads created before tool registration remain resumable with their original capabilities, and do not gain these tools retroactively. On native thread resume, the live process restores Hatch ownership before reporting ready and shuts it down with the process generation. A fresh thread has no retained Hatch authority to restore. Each dynamic call is fenced to the registered tool, active thread and turn, and native item; repeated call IDs reuse one in-memory result receipt within that turn instead of repeating an external effect. Tool receipts are not Session authority or durable backup state.

The pinned app-server submits a turn before it enqueues the `turn/start` response, while its event handler can independently enqueue turn events ([turn processor](https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/codex-rs/app-server/src/request_processors/turn_processor.rs), [message processor](https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/codex-rs/app-server/src/message_processor.rs), [event handler](https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/codex-rs/app-server/src/bespoke_event_handling.rs)). The runtime holds at most 64 decoded parent lifecycle events, scoped advisories, upstream failures, and dynamic tool requests while that one admission reply is pending. It checks every thread and turn ID against the reply before replaying them in arrival order through the existing handlers; no buffered event is published or tool executed on a mismatch or timeout. A mismatch still fails the generation; the buffer adds no authority for a foreign or old turn.

Focused adapter tests prove validated failed-save history, one stop, fresh-runtime follow-up admission, and ordinary terminal-save behavior. A pinned packaged-binary test proves a held native turn can lose its process, save its partial rollout, resume the same thread in a fresh process, reconcile its old admission receipt without replay, and complete a distinct follow-up. These tests do not prove deployed backup/resume. Production proof must exercise Worker, Session actor, confirmed backup, and a new Codex turn. A Session already stopped under an earlier release cannot be retroactively repaired by a code change; its live container files and actor proof determine whether a recovery is possible.
