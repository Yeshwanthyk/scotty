to new sessions. Individual `resources` CLI commands landed in [PR #263](https://github.com/Yeshwanthyk/scotty/pull/263)
after v0.3.22; that release supports whole-catalog `sandbox push`.

## Working with agents

| Feature                       | What it does                                                                                                   | Code                                                                                          | Tests                                                                                                                      |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Live worklog                  | Follow agent conversations and work through authenticated session URLs.                                        | [Worker routes](../worker/src/index.ts), [conversation protocol](../protocol/conversation.ts) | [Worklog](../worker/test/session/session-worklog.test.ts), [conversation](../worker/test/protocol/conversation.test.ts)    |
| Browser terminal              | Attach to the sandbox's native PTY through an authenticated WebSocket.                                         | [Worker routes](../worker/src/index.ts), [terminal protocol](../protocol/session-terminal.ts) | [Terminal protocol](../worker/test/protocol/session-terminal.test.ts), [routes](../worker/test/integration/routes.test.ts) |
| Inspect and steer             | Read a warm session without waking its container, send a prompt, queue a follow-up, or interrupt work.         | [Passive controls](../worker/src/session/passive.ts), [CLI](../cli/src/commands.ts)           | [Worklog](../worker/test/session/session-worklog.test.ts), [CLI commands](../cli/effect-test/command-tree.test.ts)         |
| Agent-to-agent coordination   | Let sandbox agents create, read, inspect, steer, and interrupt sessions within their allowed repository scope. | [Container session admission](../worker/src/session/object.ts)                                | [Container egress](../worker/test/egress/container-session-egress.test.ts)                                                 |
| Live app previews             | Open Hatch, the authenticated application running in a session.                                                | [Hatch](../worker/src/hatch/)                                                                 | [Gateway](../worker/test/hatch/hatch-gateway.test.ts), [startup](../worker/test/hatch/hatch-startup.test.ts)               |
| Browser evidence and Showcase | Review matched before/after screenshots, assertions, and recorded video.                                       | [Evidence](../worker/src/evidence/)                                                           | [Evidence tests](../worker/test/evidence/)                                                                                 |

Agent-to-agent coordination currently requires matching repository identities and a warm Cloudflare
source session. It is not unrestricted installation-wide access. See the
[coordination rules](cli.md#agent-to-agent-coordination).

Hatch is a live app, not a deployment. Evidence is retained output, not the live app. See
[Hatch and browser evidence](hatch.md) for configuration and the before/after workflow.
