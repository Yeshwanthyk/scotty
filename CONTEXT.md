# Scotty

Scotty runs durable coding-agent sessions while keeping installation identity, execution
infrastructure, and user credentials explicit.

## Language

**Installation**:
A user-chosen Scotty deployment name within a Cloudflare account. It owns a namespaced Alchemy
stack and resource set. It is never inferred from a username, machine name, repository, or account.

**Ready Installation**:
An Installation whose current evaluated capabilities support its primary control path and at least
one new Session route. Readiness is derived from current facts, not stored as a lifecycle state.

**Session**:
A durable unit of agent work with one workspace, lifecycle, repository branch, and immutable
execution provider.

**Connected Session**:
A Session with a live authenticated terminal-client input and event relationship. Connection is a
client relationship, not a Session lifecycle state.

**Hatch**:
An authenticated, interactive view of an application service currently running in a Session. A
Hatch is live access, not retained evidence or a deployment.
_Avoid_: Portal, preview, live view

**Compute provider**:
A plugin that supplies the machine that runs a Session. Cloudflare and trusted runners are compute
providers.

**Plugin**:
An item that an installation administrator explicitly declares for Scotty. Each Plugin has one
type: compute provider, Pi extension, Skill, or Sandbox tool.

**Private configuration**:
The installation administrator's strict declarative file at `~/.config/scotty/config.json`. It
selects one Installation, declares Plugins, and defines one Sandbox setup without storing
credentials or live control-plane state.

**Deployed snapshot**:
The one active, revisioned, digest-pinned result of a successful Sync. New Sessions use it;
existing Sessions retain the snapshot they started with.

**Pi extension**:
Code loaded into Pi that can add agent tools, commands, event handling, or other Pi behavior.

**Sandbox tool**:
An executable or runtime capability installed in the Sandbox. It can be used by the shell, Pi, or
a Pi extension, but it does not change Pi behavior by itself.

**Sandbox setup**:
The installation-wide ordered selection of Sandbox tools, Skills, and Pi extensions that a new
Session receives. An existing Session keeps the setup that it started with.

**Pi behavior settings**:
The non-secret Pi preferences declared in Scotty's private configuration and pinned in the
deployed snapshot. They may select model, provider, thinking, retry, compaction, display, and
message behavior. They cannot select executable resources, host paths, project trust, network
routing, Session storage, credentials, or Scotty transport controls.

**Standard setup**:
The safe Sandbox setup generated by `scotty init` when an administrator has no existing Scotty
configuration. It selects the versioned standard tool Plugin and Pi-only subagents while keeping
Hatch and evidence capture installed but dormant. It does not require Pi on the local machine.


**Mirror**:
The Installation-owned Cloudflare Artifacts copy of verified GitHub commits for registered base
refs. Refresh never changes an existing Session Fork.

**Fork**:
An isolated Cloudflare Artifacts repository created from one exact verified Mirror commit for one
Session. The Session may read and write only its own Fork.

**Publish**:
Validate one explicit agent-created commit and send that exact prepared point through the
repository bridge to a controlled GitHub branch and pull request. Publish never creates a hidden
commit, rewrites history, or implies that the pull request merged.

**Prepared Publish point**:
The immutable tuple of Session head, Fork revision, verified GitHub base, check policy and results,
deployed snapshot digest, evidence, and pinned GitHub credential generation approved for one
Publish operation. Any changed input requires a new preparation.

**Controlled Publish branch**:
A deterministic GitHub branch whose ownership Scotty proves from its repository control record,
expected head, and pull-request identity. Its name alone does not prove ownership.

**Sync**:
Bring the deployed installation in line with its private local configuration. A sync can update
files, the container, or the control plane.

**Runner**:
A user-named Scotty service on a user-controlled Linux machine. Runner registration, desired state,
connection state, and session assignment are owned by the control plane.

**Control plane**:
The public Worker plus the Config, Credential, Auth, Session, and Runner Durable Objects. It owns
identity, lifecycle, credential policy, installation metadata, and provider selection.

**Runtime**:
The Pi agent, workspace, RPC supervisor, and Git processes executing inside provider compute.

**Projection**:
A non-secret, rebuildable view of authoritative Durable Object state stored in KV for listing.

**Authoritative state**:
A fact that exactly one owner may change. Derived views, caches, provider observations, and runtime
state may describe it but cannot replace it.

**Activation record**:
The Installation's current revisioned pointer to its active deployed snapshot. It is current-state
authority, not a configuration history.

**Installation secret boundary**:
The Account Secrets Store wrapping key, Credential object ciphertext, and provider-local broker
memory that together protect Installation credentials. No single product record stores plaintext.

**Workspace backup**:
An immutable recovery payload for one Session workspace. The Session owns which backup is current;
R2 owns the referenced bytes.

**Evidence artifact**:
An immutable screenshot, video, or other retained proof captured or added for a Session and shown
through authenticated views. It is distinct from a Hatch, workspace backup, deployed snapshot
bundle, and Cloudflare Artifacts Git content.

**Warm Session**:
A Session whose provider compute, restored workspace, Fork, Pi RPC, and credential broker are
usable. Hatch and screenshot or video capture are available capabilities but may remain dormant.

**Stopped Session**:
A Session with no active compute or Hatch access and a recorded stop reason, current checkpoint
when one exists, and allowed recovery action. An explicit Resume from a complete checkpoint
restores the same Session.

**Checkpoint**:
One complete restorable point that pairs an exact Artifacts Fork revision with an immutable R2
workspace backup. Partial Fork or backup state is not a Checkpoint.

**Hard cap**:
The mandatory deadline for one Warm runtime activation. Reaching it checkpoints and stops compute;
an explicit Resume of the same Session starts a new bounded activation.

**Repository bridge**:
The installation control path that transfers and verifies exact public or private GitHub commits
into a Mirror and publishes checked Fork revisions back to GitHub.

**Session sentinel**:
A stable Session-bound value that is useful only through the assigned provider broker and current
runtime epoch. It is not a GitHub or Cloudflare Artifacts credential.

**Git broker**:
The provider-local boundary that validates a Session sentinel and applies short-lived Artifacts
authority outside Session compute while streaming Git traffic to the Session's Fork.

**Credential**:
An administrator-named Installation secret with one typed delivery policy and encrypted generations.
The reserved names `pi` and `github` supply the core login paths.

**Credential generation**:
One encrypted version pinned by future Sessions at Create. Administrator replacement changes the
current generation for future Sessions without changing existing Session grants.

**Delivery adapter**:
A host-side policy that applies one credential to an approved provider, protocol, and target
without placing the real value in Session compute.

**Browser owner**:
The one everyday Auth administrator that may issue pairing grants, revoke standard clients, and
start ownership transfer. It is not the root recovery credential or the Worker itself.

**Paired client**:
One terminal device identity authorized by Auth for normal CLI and TUI use. It may revoke itself
but cannot pair another device, change browser ownership, or use root recovery authority.

**Local operation hint**:
A secret-free local journal that identifies an open or ambiguous remote operation and its safe
reconciliation point. It never proves the remote result and has no age expiry while unresolved.

**Runner certification**:
The full setup or update proof bound to one exact Runner binary, protocol, OCI image, Pi release,
capability manifest, and isolation contract. Each connection must attest the same digests and pass
light health before the Runner can become create-capable.

**Runner control lease**:
The renewable local deadline for one active Runner assignment. Broker access stops when the link
drops. If renewal does not return within five minutes, or the earlier hard cap expires, the Runner
quiesces Pi and stops compute locally.

**Runner abandon**:
An explicit result for a permanently lost host. It revokes Runner identity and records unresolved
host-cleanup debt without claiming that containers, workspaces, or local state were deleted.

**Clean cutover**:
The replacement of unshipped Scotty development state with one canonical system. Each
implementation slice moves all callers, proves the new contract, and removes the old path before
merge. A guarded repository-only reset clears proven Scotty-owned development state before a fresh
deployment while preserving external GitHub repositories, branches, pull requests, and human
metadata.

**Release candidate**:
One exact executable, OCI image, deployed payload, protocol, browser asset set, and setup input set
submitted to the full alpha gates. A vertical fix creates a new candidate. A blind rerun does not
change a failed candidate into a passing one.
