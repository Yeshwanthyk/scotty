# Product

## Register

product

## Platform

web

## Users

Scotty is optimized first for a small development team running several cloud coding sessions across repositories. Team members need to create workspaces, move between long-running conversations, understand lifecycle state, recover interrupted work, inspect browser evidence, and remove sessions without guessing which state is authoritative.

## Product Purpose

Scotty makes cloud coding fast while keeping each session's workspace, agent conversation, lifecycle, artifacts, and recovery controls understandable. Success means a teammate can enter the product, find the right session, understand what it is doing, and take the next valid action without waiting on unexplained UI or interpreting infrastructure errors.

## Positioning

The fastest trustworthy path from a repository to a live cloud coding session.

## Brand Personality

Calm, precise, responsive. The interface should feel composed under concurrency: direct language, crisp hierarchy, restrained feedback, and motion that preserves continuity without delaying work.

## Anti-references

Do not turn Scotty into a generic SaaS dashboard. Avoid interchangeable card grids, excessive navigation chrome, decorative status colors, and summary metrics that displace the active development workflow. Do not hide workspace authority behind a chat-only presentation or expose raw provider errors as product states.

## Design Principles

- Make the next useful action immediate; cloud setup and recovery can take time, but the interface must never feel inert.
- Show authoritative lifecycle state and freshness clearly without making infrastructure vocabulary the user's burden.
- Preserve continuity across navigation, streaming conversation updates, long histories, retries, and reconnects.
- Keep session work primary; fleet and administrative context should support the task instead of competing with it.
- Use one coherent interaction and state vocabulary across every route.

## Accessibility & Inclusion

Preserve the current accessibility baseline throughout the migration. Maintain semantic structure, keyboard operation, visible focus, status announcements, readable contrast, and reduced-motion behavior already present in the product. A broader WCAG certification effort is outside this lane.
